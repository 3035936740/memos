# Internationalization / 国际化

Memos Plus uses i18next and react-i18next. Supported language codes are defined in
[`web/src/locale-codes.json`](../web/src/locale-codes.json); there are currently 44.
The interface catalogs cover the same English reference keys in every supported
language. Catalog completeness is a structural check, not a guarantee of native
translation quality.

## Language selection

The preference order is the signed-in account setting, this browser's saved
choice, the administrator's first-visit default, then Simplified Chinese for
backward compatibility. Selecting **Automatic** stores `auto`
as the preference, rather than saving the language it happened to resolve to.
Automatic mode checks `navigator.languages` in order, matches supported regional
and base languages, and falls back to English if none match. Chinese variants
resolve to Simplified or Traditional Chinese. A browser `languagechange` event
updates automatic mode; explicit language choices stay fixed.

The selected preference is stored in `localStorage` as `memos-locale`. Signed-in
users also save it to their existing user settings. The document's `lang` and
`dir` use the resolved language. Arabic, Persian and Hebrew retain RTL layout.
No database migration or new API field is needed for `auto`.

Automatic selection is available in the language menus and the administrator's
first-visit language setting. It is intentionally excluded from Daily Question
translation-language selectors: those identify a content language, not a browser
preference. User-authored content, tags, code and diagnostic details are not
automatically translated.

## Catalogs and contributions

- `web/src/locales/<code>.json` contains the existing base catalog.
- `web/src/locales-custom/<code>.json` extends it with Plus features and overrides.
- Custom catalogs merge recursively over the base catalog; English remains the
  fallback for future missing keys or loading errors.
- Use `useTranslate()` in React components. Resolve labels inside components or
  functions receiving `t`, so language changes do not leave module-level labels
  frozen in the old language.
- Keep `{{parameters}}` unchanged and use interpolation instead of concatenating
  language-dependent sentences. Supply `count` for plural messages and include
  the locale's CLDR plural categories. Do not translate routes, API identifiers,
  code samples, provider names or user-entered titles.

Previously missing translations were supplemented with machine-translated drafts
during this pass. Existing translations were retained, except for invalid empty
values. New core Simplified Chinese, Traditional Chinese and English UI copy was
also edited directly. Native-language review is welcome, particularly for long
administration explanations, grammatical agreement and plural forms. A copied
localized plural form can still need grammatical refinement even when all
required categories are present. Please submit focused translation PRs to this
repository; no external translation service is required to build or run it.

## Checks

The 365 built-in Daily Questions live in `web/src/utils/daily-questions/<code>.ts`
for all 44 UI language codes. Question indices remain identical across banks, so
switching languages changes the wording, not the selected question or yearly
schedule. Readers load their own bank on demand, falling back to English for an
unsupported language or a failed localized chunk. The admin editor previews one
translation at a time; converting a built-in question to an editable custom one
loads all banks and preserves its translations. New bank translations are
machine-assisted drafts with structural and duplicate checks; native review is
still welcome. There is no external translation request at runtime or build time.

```bash
pnpm --dir web lint:i18n
pnpm --dir web lint
pnpm --dir web build
```

`lint:i18n` reads both catalog layers and checks every supported locale for missing
reference keys, invalid values, empty nonempty-source translations, interpolation
changes, leftover translation markers and missing plural categories. It runs in
the frontend CI workflow. Translations continue to load lazily; this work does not
eagerly bundle all languages into the initial application chunk.

The same check also requires one bank per supported language, exactly 365 unique
nonempty questions per bank, a 200-character Unicode limit, no translation
markers, and no entire untranslated English copies outside the English locales.

## 中文说明

当前界面支持 44 种语言。账号语言、本地选择、管理员首次访问默认语言依次优先；
均未设置时保留简体中文默认值。选择“自动”后保存的是 `auto`，
每次启动按浏览器语言列表匹配；无支持项时回退英文。手动选定的语言不会随浏览器改变。

基础翻译位于 `locales`，Plus 扩展位于 `locales-custom`。本次保留原有译文，
为缺失内容补充机器翻译初稿；涉及长说明、语法和复数变化的部分仍欢迎母语使用者校对。
语言文件完整不等于翻译质量已经全部通过人工审核。用户内容、标签、代码和原始诊断信息不做自动翻译。

新增文案应同步更新所有支持的语言，并运行上面的检查命令。不要修改 `{{参数}}`，
不要把语言相关的句子拆成固定语序拼接。每日一问的内容语言选择不提供“自动”，
避免把浏览器偏好误存为题目语言。

365 道默认题现已覆盖全部 44 种界面语言，各语言保持相同题号；未知语言或译文分块
加载失败时回退英文。题库按需加载，后台展开单题时一次只预览一种语言。新增译文
包含机器辅助翻译，已检查完整性、重复和长度，仍欢迎母语使用者校对语气和语义。
