# 每日一问后端对接

对应 `backend-daily-question.md`。主页组件、365 题默认题库、语言选择和每日洗牌算法仍由前端负责，后端不计算当天题目。

## 配置字段

沿用 `instance/settings/GENERAL` 的读取、更新接口及管理员写权限。匿名访客可读取以下字段。

| Proto 字段（编号） | JSON / TypeScript 字段 | 默认值 |
| --- | --- | --- |
| `daily_question_seed`（28） | `dailyQuestionSeed` | 初始化时生成的 16 位十六进制字符串 |
| `daily_questions_json`（29） | `dailyQuestionsJson` | `""`，使用前端内置题库 |
| `disable_daily_question`（30） | `disableDailyQuestion` | `false`，开启每日一问 |

`dailyQuestionsJson` 本身是字符串，例如 `"[\"今天有什么值得记录的事？\",\"最近学到了什么？\"]"`，不是直接嵌套的 JSON 数组。

新增管理界面位于 **管理 → 系统 → 高级 → 每日一问**。题库默认折叠，每页只渲染 20 条；单题和可选翻译可以继续折叠。支持添加、批量添加、删除、编辑、种子修改／重新随机、恢复默认题库和启停；按系统页底部“保存”后生效。

为保留删改后的内置三语对应关系，数组现在兼容三类条目（旧字符串仍然有效）：

```json
[
  {"builtin": 0},
  "不指定语言的旧自定义题",
  {"text": "What made you smile?", "locale": "en", "translations": {"zh-Hans": "什么事情让你笑了？", "zh-Hant": "什麼事情讓你笑了？"}}
]
```

`builtin` 为 0–364 的内置题索引，只能单独出现。自定义题的 `locale` 可省略／留空（不指定），也可选择全部界面语言；`translations` 的语言键与 `web/src/locale-codes.json` 的 i18n 列表一致。显示顺序为访客语言、对应基础语言、英文，最后保留旧题默认文字（未提供英文时）。内置题仍为简中、繁中、英文三语，其他语言使用英文。每种文字分别受 200 字上限和文本审核约束。未知字段、非法语言或非文字翻译会被拒绝。

语言列表变更后运行 `node web/scripts/generate-locale-codes.mjs` 同步后端校验；后端测试会检查两侧列表一致。翻译编辑器按需展开，每次只编辑一种语言，避免同时挂载大量文本框。

不足 365 题时，前端每一轮会重新洗牌，整轮使用完再进入下一轮。例如 67 题会使用完整 5 轮共 335 天，再从第 6 轮的不重复排列中取 30 题。保留原始 365 题时第一轮种子算法不变；闰年第 366 天依旧使用独立种子抽取。

General 更新接口仍按现有逻辑保存完整配置。编辑其他设置时，请带回读取到的种子和题库；种子空字符串表示**主动重新随机**，题库空字符串表示**恢复默认题库**。成功后使用接口返回的值刷新表单。

## 初始化和校验

- 新站使用 `crypto/rand` 生成 8 字节、编码为 16 位十六进制种子。SQLite、MySQL、PostgreSQL 均增加 `0004__daily_question.sql` Plus 迁移，由 Go 迁移钩子补种子。
- 迁移只修改缺失或为空的种子，保留其他 General JSON 字段；启动、再次迁移和演示站重置不覆盖已有种子。文件管理的 General 若未指定种子，会继承数据库中的持久种子。
- 管理员指定的非空种子须符合 `[A-Za-z0-9_-]{1,64}`；清空后立即生成新种子再保存。
- 题库须是上述 JSON 题目数组；逐题去掉首尾空白，再移除空题和重复题。全部移除时保存为空字符串。界面保留至少一题，停用请关闭开关；恢复默认使用明确的“恢复默认题库”操作。
- 每种题目文字及翻译最多 200 个 Unicode 字符；输入数组最多 2000 项；输入及规范化后的 JSON 均最多 256 KiB。不接受 `null`、数字或不符合上述结构的数组项。
- 自定义题目通过现有文本审核入口，包含屏蔽词检查以及站点已开启的 AI 文本审核。拒绝审核或审核服务失败时不保存配置。
- 格式错误返回 `InvalidArgument`，种子错误信息包含 `daily_question_seed`。未登录和普通用户无法修改配置。

这些字段保存在现有 General JSON 中，无需新增表列，也无需修改各驱动的 `LATEST.sql`。
